# Archetype library (shared layer)

An archetype is a brand-agnostic layout that encodes design principles as **slots**, a **hierarchy** order, **content budgets**, **bounded variation** and **checks**. It never carries a brand value: every color, size and font comes from `--brand-*` tokens via `_shared/base.css`, every allowed choice from `--v-*` variation vars.

Each archetype folder holds:

- `spec.md` — a System Design module (Tessor contract: frontmatter `title/scope/owns/see-also/implements`, `## Decisions`, `## Never do`, a `tessor-props` block for the variation parameters). Human-readable source of truth.
- `inputs.schema.json` — the machine contract the renderer and checks read: it starts with `"contractVersion": "1.0"` (a schema without it is refused). It declares slots and budgets, hierarchy, variation values, checks, fallbacks. Each text slot declares a `role` level: `h1` | `h2` | `h3` | `body` | `label` | `data-snippet`. The display face belongs to `h1`, `h2`, `h3` and `data-snippet`; `body` and `label` use the body face. The `role-face` check enforces it against the computed font, and the renderer stamps `data-role="<level>"` on every filled slot. A slot of `"kind": "image"` (with `"bleed": true` and `"alpha": "any" | "required" | "none"`) takes a row value of `{ "src", "focal": [x, y], "alt" }`: `src` is a file under `brand/assets/photos/`, `focal` is 0..1 of the source and drives the crop. Schemas with an image slot also run three checks, `alpha`, `crop` and `image-contrast`, that measure the real pixels rather than the CSS.
- `template.html` — the fragment (see `CLAUDE.md` → Contracts → Template). An image slot sits in a `.pg-photo` wrapper, and `base.css` turns the row's focal point into `object-position`.

A text slot may name a `"scale"` group (contract 1.5, optional): its values are numbers (with an optional shared unit), and the renderer stamps each as `--pg-scale-<slot>`, its fraction of the group's largest value (0..1), on the frame. A template draws a bar as `calc(var(--pg-scale-<slot>, 0) * <track>)`, so bars start at zero on one linear scale (`slides/chart`). A row whose values are not one number each, mix units or go below zero is refused (budget rule `scale`).

Two optional schema fields (contract 1.4): `"ratios"` lists the formats the layout serves (a subset of its use-case's ratios in `poligraf.config.json`), and `"proposal": "optional"` tells the doctor the layout serves a job not every brand has, so its proposal is not required.

Six use-cases ship: `social-post` (headline, stat, quote, event, offer, list, hiring, contrast, carousel, partnership: ten sample layouts, plus the reference announcement), `banner` (link-preview at 1200×630, profile-cover at 1584×396, and since contract 1.5 the web banner form: the display ad units leaderboard 728×90, rectangle 300×250, half-page 300×600, skyscraper 160×600, billboard 970×250 and mobile 320×100, the site hero at 1920×600, and custom at any size), `email` (header at 1200×400), `print` (flyer, poster, menu, offer-flyer, card-front, card-back, postcard, rack-card, table-tent, sticker), `slides` (16 layouts at 1920×1080 (16:9): title, title-speaker and agenda to open; section, statement, bullets, two-column, stat, numbers, quote, process, comparison and chart for the body; thanks-contact, next-steps and questions to close; every slide shares one chrome from `base.css`, logo top left and the optional `footer` and `page` slots along the bottom edge, so a deck reads as one thing) and `mockup` (tote-bag, cup-sleeve, shop-window, phone-in-hand, laptop-screen, bus-shelter, card-on-desk, t-shirt, lanyard, menu-on-table; prompt recipes, below). Print frames are trim sizes at 150 dpi (A4 1240×1754, A5 874×1240, A6 874×620 and 620×874, DL 585×1240, business card 502×325, sticker 450×450), so `minTextPx` 17 is 8pt on every one; the proof PNG at `render.scale` 2 is 300 dpi, and bleed and PDF are a later step. Sizes are in `cqi`, so 1cqi is 1% of the frame width: 10.8px on a post, 12px on a link preview or an email header, 15.84px on a profile cover, 19.2px on a slide, 7.28px on a leaderboard. Display ads show at 1x, so their minimum text size is set per ratio (`minTextPxByRatio`, 1.5). A custom frame is a size container: its layout picks a shape with `@container frame (min-aspect-ratio: …)` and sizes type in `cqmin` (1% of the short side), never `@media`.

Two social-post layouts use contract 1.5. **carousel** is one slide with a `beat` (cover, point, close); its slots declare the beats they belong to with `when`, and a whole carousel is a generator with ordered `frames` (one sample per frame, in order, shown as one strip on the contact sheet; a frame may be another layout, such as a stat). **partnership** is an "A × B" lockup: the brand logo, a × drawn in CSS, and a partner mark the row names (`partnerLogo`, a file under `brand/assets/`, refused when missing or outside the folder; `logo-visible` measures it as well, and its integrity is a review item).

**Prompt layouts (contract 1.5).** A schema with `"kind": "prompt"` is a recipe, not a frame: its folder holds `spec.md`, `inputs.schema.json` and `prompt.md` (a fill-in prompt between `<!-- BEGIN PROMPT -->` and `<!-- END PROMPT -->`, with `{{placeholders}}`), and no `template.html`. One slot of `"kind": "artwork"` takes a PNG of a sample that passed, in a format its `accepts` patterns name (`social-post/*@1:1`, `print/*`). Variation values carry `phrases`, the words the prompt reads. `output` gives the size to ask for. `review` lists the checks the owner's agent judges by eye (id, plain words, what to look at, the fix line to add to the prompt), reported as pass, fail or not measured; the spec's Checks line lists them. The engine never renders a prompt layout: `npm run mockup` fills the prompt and writes `out/<run>/mockup.json`, and the owner's own agent sends both to the owner's own image model (`skills/poligraf--mockup.md`).

`<use-case>/select.md` is the decision tree from content to archetype, with fallbacks when a budget is exceeded or a slot is missing.

Adding an archetype means all three files (`prompt.md` in place of `template.html` for a prompt layout) plus a `select.md` branch, written together, spec first. In a fork of Brand Asset Maker (BAM), the owner or a designer may add one, usually from a gap note that ended in ask (c) (`workshop/gap-note.md`). Never add a template without its spec and schema.
